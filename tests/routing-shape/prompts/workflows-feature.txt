Add a plugin system to storekit. The design is settled and written down here, so nothing in it needs deciding: a plugin is a folder under plugins/ holding a plugin.json manifest (name, version, the storekit version range it supports, and which lifecycle hooks it implements) and an index.js; a loader in modules/plugins.js discovers plugins, validates each manifest against a schema and refuses incompatible versions with a clear error; four lifecycle hooks (init, beforeLoad, afterLoad, shutdown) are wired into lib/store.sh and modules/router.js; bin/app.sh gains a `plugins` command with list, enable and disable; the enabled set persists in a config file through modules/config.js; one example plugin ships under plugins/example; docs/plugins.md explains how to write one; and every piece gets its own tests. Build the whole feature.
